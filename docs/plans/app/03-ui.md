# 03 UI (`apps/spikes-ui`)

## 1. Stack

- **Tauri v2** shell; **React 19 + TypeScript + Vite**; **Redux Toolkit** for app state (the v1 slices port),
  with live frame data kept *outside* Redux in typed-array ring buffers (re-rendering React per frame is too slow).
- **Material UI** (`@mui/material` 9.x, with `@mui/icons-material`), MUI's React implementation of Google's
  Material Design, replaces v1's Fluent UI (`@fluentui/react` 8). One MUI theme (light and dark, following the
  system) is the source of every colour; Fluent components map to MUI ones (`Stack`/`Grid`, `Drawer`, `Tabs`,
  `Dialog`, `Slider` for the speed control, `Snackbar` for notices, `Table` for small lists).
- **Monaco** for `.boo` editing: the v1 `spikes` language (tokens, completions, hover docs, ~1,500 lines with
  tests) ports nearly as is, updated for the v2 keys (`MOD`, `RCP`, `REL`, `RES`, `HIP`, `SNT`). Diagnostics come
  from the Rust parser (`CreateSession`/`UpdateDescription` errors), so the editor and the engine never disagree.
- **three.js** for the 3D network: `InstancedMesh` for neurons (one draw call for 100k+), `LineSegments` for
  connections (optional, filtered by selection), spike flashes as a per-instance attribute updated from frames.
- **Charts: `stream-charts` 2.1** (v1 used 1.0.1). It draws each chart on a single canvas, outside React's render
  cycle, from an RxJS data source, which fits frames directly: the frame decoder pushes each frame's sections into
  RxJS subjects that feed the charts' data sources.
  - `<RasterPlot>`: spikes, one row per neuron. Rows are the current selection (a group, a region, the neurons in
    view), up to a few hundred; whole-network activity is shown as population rates.
  - `<ScatterPlot>`: membrane traces of selected neurons (every update, as recorded), weights over time,
    population rates, and the timing-health readouts (lag, events/s, lookahead).
  - `<BarPlot>`: spike-count or ISI histograms per group.
  - `<PoincarePlot>`: ISI return maps (t_{n+1} vs t_n) for an inspected neuron, useful for bistable and resonator
    neurons.
  - Tuned with `dropDataAfter` (data source), `windowingTime` and `dataUpdatePeriod` equal to the frame interval
    (chart), so scrolling stays smooth at 60 fps.
  - Colours come from the MUI theme: a small adapter turns `theme.palette` into `stream-charts` colour props
    (chart `color`/`backgroundColor`, `seriesStyles`, tooltip, tracker and legend styles), so charts switch with
    light/dark mode.
  - v1's `SpikesChart`, `WeightsChart` and `SensorSimulation` are ported to the 2.x API (data sources and
    generators instead of `seriesObservable`, `Datum` is `{x, y}`, root imports only; see the library's
    "migrating from 1.x").
- **Vitest** for unit tests, **Playwright** for end-to-end tests against `spikes-server` (the same UI as a web
  app), Tauri's WebDriver for a few desktop smoke tests.

## 2. Screens

| Screen | Contents | From v1 |
|--------|----------|---------|
| Projects | Open/create a project directory; recent projects; import a v1 `.spikes` project | `SimulationManager`, `ProjectConfig` |
| Network editor | Monaco with live diagnostics, templates, a summary of the parsed network (neurons, groups, connections, modulators) | `NetworkEditor`, `language/*` |
| Sensors and inputs | Declare sensors (channels, encoding, target neurons), see connected sensors live (rate, lateness, a `stream-charts` view of their channels), the built-in microphone sensor (Web Audio filterbank), synthetic input actors; v1-style scripted sensors run in a web worker as just another external sensor | `SensorsEditor`, `SensorSimulation` |
| Run | Build/start/pause/step/stop, **speed slider** (×1/64 … ×64, log scale), sim-time and lag readouts, timing-health panel (lag, lookahead, events/s, dropped frames, warnings), stimulus buttons, modulator "reward" button | `RunDeployManager` + new |
| Views (dockable) | 3D network, raster, weights over time, membrane traces of selected neurons, population rates, ISI histograms and return maps, neuron inspector (`QueryNeuron`), topology editor (connect/prune) | `neuralthree/*`, `SpikesChart`, `WeightsChart` |
| Recordings | List runs, open one in the same views (replay), download Parquet | new |
| Settings | Where to run (this computer / server URL + token), theme, frame rate and bandwidth budget | `settings` |

Views share a **selection** (neurons, a region, a group): selecting in the 3D view filters the raster and sets the
membrane traces, and the client sends `UpdateView` so the frames carry exact data for the selection.

## 3. The TypeScript client

```ts
interface SpikesClient {
  request<R extends Request>(r: R): Promise<ResponseFor<R>>;
  attach(session: SessionId, view: View, onFrame: (f: Frame) => void): Promise<Viewer>;
  onNotice(handler: (n: Notice) => void): Unsubscribe;
  readonly status: Observable<"connected" | "connecting" | "disconnected">;
}
class TauriClient implements SpikesClient { /* invoke + Channel */ }
class WebSocketClient implements SpikesClient { /* ws text/binary, reconnect with backoff */ }
```

`Frame` is a zero-copy view over the received `ArrayBuffer` (`Uint32Array`/`Float32Array` per section). A small
`frames` module turns frames into RxJS streams per view: `stream-charts` data sources for the charts (names from
the neuron table, times in ms from `t0_ns + offset_ns`), and typed-array buffers for the 3D view's per-instance
attributes.

## 4. Replay

Recordings are replayed by the engine: `OpenRecording` creates a read-only session that streams frames from the
Parquet files at a chosen speed, with seeking. The views don't know whether a session is live or a replay. (Reading
Parquet in the browser would need a WASM decoder; doing it in Rust keeps the UI simple and works remotely.)

## 5. Accessibility and polish

Keyboard control of the run (space = pause/resume, `.` = step, `[`/`]` = speed), light and dark themes (v1 had
both), colour schemes that are safe for colour-blind users for excitatory/inhibitory and spike density.
