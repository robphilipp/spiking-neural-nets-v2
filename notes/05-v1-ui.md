# v1 UI (`ui/e-spikes-ui`)

Electron Forge + webpack, React, Redux, react-router, Monaco editor, three.js, RxJS, threads.js workers, axios.

## Screens and features

- **Simulation project** (`SimulationManager`, `ProjectConfig`, `RunDeployManager`): open or create a `.spikes`
  project (network file, sensor file, time factor, duration). Deploy (REST), build (WebSocket), start, stop, delete.
  Includes a simulation timer.
- **Network editor** (`NetworkEditor` + `language/*`): Monaco with a custom `spikes` language for `.boo` files.
  Includes tokens, regexes, completions (about 1,500 lines), hover docs and a language configuration, all with unit
  tests. Has templates for new networks.
- **Sensor editor** (`SensorsEditor`, `sensors/compiler.ts`, `SensorSimulation`): edit the sensor JS, compile it in
  a worker, and preview its signal output in a chart.
- **Visualization**:
  - 3D network (`visualization/neuralthree/{Network,Neurons,Connections,Synapses}`): neurons placed at their
    coordinates, connections drawn, spikes highlighted, with color schemes.
  - `SpikesChart`: spike raster over time.
  - `WeightsChart`: connection weights over time.
  - `NetworkTopologyVisualization`.
- **Settings**: server host and port, Kafka, templates, theme (light and dark).
- **Workers**: `workers/networkManager.ts` owns the REST calls and the WebSocket. It turns incoming events
  (`neuron`, `connection`, `learn`, `fire`, `networkCreated`) into an observable for Redux.
  `workers/sensorSignals.ts` runs the sensor observable.
- Persistence: `repos/*` store sessions, app settings, project files and themes on disk through Electron.

## Carrying it over to Tauri v2 (TypeScript)

- Most of the React code can move over: Monaco language support, three.js scenes, charts, Redux slices. Electron's
  `ipcMain`/`fs` calls in `repos/*` become Tauri commands or `@tauri-apps/plugin-fs`.
- The network-manager worker is the seam. Today it speaks REST + WebSocket to a remote server. In v2 it can speak
  either **Tauri IPC** (embedded backend) or **WebSocket** (remote cluster) behind one TypeScript interface (see
  note 06).
- Event volume: 3D views and rasters need batched, binary-encoded event frames (for example, one batch per
  animation frame), not one JSON message per spike.
